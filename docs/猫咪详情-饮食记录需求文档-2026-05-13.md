## 2. 背景与目标

当前猫咪详情页已经有【基本信息】【健康记录】【体重记录】【相册】4个页签，但缺少对“每天吃了什么、换粮换到哪一步、零食和补剂是否超量、最近有没有因为饮食变化出现软便/呕吐/食欲下降”的持续记录。

新增【饮食记录】页签的目标：

1. 让每只猫都能沉淀自己的长期饮食档案，而不是只靠聊天或临时备注记忆。
2. 把“主粮计划”和“实际喂食”分开记录，既能看计划，也能看执行情况。
3. 支持换粮期管理，尤其是 7 日/多日渐进换粮法。
4. 支持记录罐头、零食、羊奶粉、补剂/保健品等非主粮摄入。
5. 为体重变化、软便、呕吐、食欲波动提供饮食侧排查线索。

## 3. 外部资料结论

这次在 2026-05-13 查阅的资料，比较一致地支持以下产品设计方向：

| 结论 | 对产品的启发 | 来源 |
|------|-------------|------|
| 主粮应优先记录是否为“完整均衡（complete and balanced）”以及适用生命阶段 | 饮食档案里应记录品牌、品名、类型、适用阶段、是否主食/零食 | [FDA: Complete and Balanced Pet Food](https://www.fda.gov/animal-veterinary/animal-health-literacy/complete-and-balanced-pet-food) |
| 湿粮含水量高，能帮助提高总摄水；干粮与湿粮不能只看重量，要看热量和含水 | 饮食记录里应支持“湿粮/干粮/冻干/鲜食/羊奶粉”等类型，并支持水分/加水备注 | [Cornell Hydration](https://www.vet.cornell.edu/departments-centers-and-institutes/cornell-feline-health-center/health-information/feline-health-topics/hydration) |
| 换粮通常建议按比例渐进进行；敏感猫可拉长到约 3 周 | 需要单独的“换粮计划”对象，支持旧粮/新粮比例、步进天数、异常反应记录 | [VCA Weight Reduction Plan for Cats](https://vcahospitals.com/know-your-pet/creating-a-weight-reduction-plan-for-cats) |
| 饮食变化可能引起腹泻；严重腹泻、呕吐、食欲下降等需要及时关注 | 换粮和喂食日志里要能快速记录软便、呕吐、拒食，并提供风险提示 | [VCA Diarrhea in Cats](https://vcahospitals.com/know-your-pet/diarrhea-in-cats) |
| 营养史应记录“24 小时进入嘴里的所有东西”，包括主粮、零食、补剂、用于喂药的食物 | 页面不能只记猫粮，必须覆盖零食、补剂、喂药搭配食物 | [Pet Nutrition Alliance: Nutritional History](https://petnutritionalliance.org/resources/nutritional-assessment-procedure/nutritional-history/) 、[WSAVA Diet History Form](https://wsava.org/wp-content/uploads/2020/01/Diet-History-Form.pdf) |
| 营养建议至少要包含：吃什么、吃多少、吃几次、如何跟进 | UI 应区分“喂养计划”和“实际执行”，并带跟踪提醒 | [Pet Nutrition Alliance: Nutritional Recommendation](https://petnutritionalliance.org/resources/nutritional-assessment-procedure/nutritional-recommendation/) |
| 零食、补剂、喂药伴食都应被视为额外摄入；零食热量建议低于每日总热量的 10% | 系统应支持零食热量占比提示，并把补剂/喂药伴食纳入统计 | [WSAVA Feeding Treats to Your Cat](https://wsava.org/wp-content/uploads/2024/06/Feeding-treats-to-your-cat-v2.pdf) |
| 过敏/食物排查时，补剂、牙膏、带味药物也可能干扰判断 | 针对“排查过敏/肠胃敏感”场景，应允许把补剂和喂药伴食单独筛选 | [VCA Elimination-Challenge Diet Trial](https://vcahospitals.com/know-your-pet/implementing-an-elimination-challenge-diet-trial-cat) |
| BCS 和体重应结合饮食长期观察 | 饮食页签建议展示最近体重、BCS 备注入口或跳转能力 | [WSAVA Body Condition Score](https://wsava.org/wp-content/uploads/2020/01/Cat-Body-Condition-Scoring-2017.pdf) 、[WSAVA Calorie Needs for Healthy Adult Cats](https://wsava.org/wp-content/uploads/2020/07/Calorie-Needs-for-Healthy-Adult-Cats-updated-July-2020.pdf) |

## 4. 我建议的产品范围

建议不要把【饮食记录】做成单一表单，而是做成“1 个页签 + 4 个子模块”：

1. 当前喂养方案
2. 每日喂食记录
3. 换粮计划
4. 补剂/保健品疗程

这样能同时覆盖“长期配置”和“日常流水”，后续也更容易做统计。

---

## 5. 页签结构建议

### 5.1 页签位置

建议把猫咪详情页页签顺序改为：

`基本信息` / `健康记录` / `饮食记录` / `体重记录` / `相册`

原因：

1. 饮食和健康、体重关系更近，应该放在体重前。
2. 用户给猫记东西时，通常会先看健康与饮食，再看长期趋势。

### 5.2 页签首页摘要卡

进入【饮食记录】页签后，顶部先展示 4 张摘要卡：

1. 当前主粮
   - 当前主粮名称
   - 干粮/湿粮
   - 每日计划量
   - 最近更新时间
2. 当前换粮状态
   - 未换粮 / 换粮中 / 已完成
   - 今日比例
   - 第几天 / 共几天
3. 今日摄入概览
   - 主粮次数
   - 罐头次数
   - 零食次数
   - 补剂次数
4. 最近异常
   - 软便
   - 呕吐
   - 食欲下降
   - 拒食

## 6. 功能需求

### 6.1 模块 A：当前喂养方案

用途：记录“这只猫目前理论上应该怎么吃”。

建议字段：

| 字段 | 说明 |
|------|------|
| 方案名称 | 例如：5月成猫维持方案、肠胃恢复期方案 |
| 生效日期 | 方案开始执行时间 |
| 主粮类型 | 干粮 / 湿粮 / 混喂 / 冻干 / 处方粮 / 其他 |
| 品牌 | 如皇家、渴望、巅峰等 |
| 产品名 | 精确到具体商品 |
| 适用阶段 | 幼猫 / 成猫 / 老年 / 全阶段 / 处方 |
| 是否完整均衡主食 | 是 / 否 / 待确认 |
| 每日计划总量 | 支持 g / 罐 / 袋 / ml / 勺 |
| 每日喂食频次 | 1 次 / 2 次 / 3 次 / 自由采食 / 自定义 |
| 建议热量 | 可选，单位 kcal/天 |
| 饮水辅助 | 湿粮补水 / 加水拌粮 / 羊奶粉 / 无 |
| 备注 | 如“肠胃敏感，换粮慢一点” |

交互建议：

1. 一个猫同一时间只允许 1 个“当前生效方案”。
2. 历史方案不能删除时，优先支持“停用/归档”。
3. 如果填写了热量和零食热量，后续可计算零食占比。

### 6.2 模块 B：每日喂食记录

用途：记录“今天实际吃了什么”。

记录类型建议支持：

1. 主粮
2. 罐头
3. 零食
4. 羊奶粉/营养液
5. 补剂/保健品
6. 喂药伴食
7. 饮水补充

建议字段：

| 字段 | 说明 |
|------|------|
| 记录时间 | 精确到日期时间 |
| 记录类型 | 主粮 / 罐头 / 零食 / 补剂等 |
| 品牌/名称 | 可手填，也可从历史中选择 |
| 规格/口味 | 可选 |
| 喂食量 | 支持 g / 颗 / 条 / 勺 / ml / 罐 / 袋 |
| 热量 | 可选，kcal |
| 是否吃完 | 吃完 / 吃了一半 / 只闻不吃 / 拒食 |
| 喂食方式 | 正常喂食 / 奖励 / 拌药 / 手喂 / 强喂辅助 |
| 关联方案 | 关联当前喂养方案或换粮计划 |
| 备注 | 如“爱吃鸡肉味，不吃鱼味” |
| 异常反馈 | 无 / 软便 / 呕吐 / 胀气 / 抓耳 / 眼屎变多 / 食欲下降 |

展示建议：

1. 默认按“今天”展示，支持切换近 7 天、近 30 天。
2. 以时间线展示，适合快速回看“一天里都喂了什么”。
3. 顶部提供“快速新增”按钮，尽量 2 到 3 步完成录入。

### 6.3 模块 C：换粮计划

这是本页签最值得单独做出来的功能。

建议字段：

| 字段 | 说明 |
|------|------|
| 计划名称 | 例如：A 粮换 B 粮 7 日过渡 |
| 开始日期 | 换粮起始日 |
| 预计天数 | 7 天 / 10 天 / 14 天 / 自定义 |
| 旧粮 | 品牌 + 产品名 |
| 新粮 | 品牌 + 产品名 |
| 原因 | 换品牌 / 年龄阶段切换 / 软便排查 / 处方粮 / 缺货 |
| 日计划明细 | 每天旧粮、新粮占比 |
| 当前状态 | 未开始 / 进行中 / 已完成 / 已中止 |
| 中止原因 | 如“出现呕吐、软便加重” |
| 观察项 | 便便、呕吐、食欲、精神、喝水量 |

默认换粮模板建议：

1. 7 日模板：`75/25 -> 50/50 -> 25/75 -> 0/100`
2. 10 日模板：每 2 到 3 天一个阶段
3. 敏感猫慢速模板：14 到 21 天

关键交互：

1. 系统自动生成每日比例，用户可手调。
2. 今日喂食记录若关联换粮计划，自动带出今日建议比例。
3. 若当天记录了软便、呕吐、拒食，换粮计划卡片出现黄色或红色提醒。
4. 换粮完成后，可一键生成“换粮总结”。

换粮总结建议自动沉淀：

1. 实际耗时
2. 是否中断
3. 哪一天出现异常
4. 最终是否适应成功

### 6.4 模块 D：补剂/保健品疗程

用途：把“长期吃一段时间的东西”从普通喂食流水中拎出来。

典型场景：

1. 补血肝精
2. 肥仔水
3. 高免因子
4. 赖氨酸
5. 化毛片
6. 肠胃粉、益生菌
7. 羊奶粉

建议字段：

| 字段 | 说明 |
|------|------|
| 产品名称 | 手填 |
| 类别 | 补剂 / 保健品 / 营养品 / 处方辅助 |
| 使用目的 | 补血 / 增重 / 肠胃 / 化毛 / 提高适口性 / 免疫支持 |
| 开始日期 | 疗程开始时间 |
| 结束日期 | 可选 |
| 频次 | 每天 1 次 / 每天 2 次 / 隔天 / 自定义 |
| 单次剂量 | 勺 / ml / 粒 / 条 / 包 |
| 喂食方式 | 直接喂 / 拌罐头 / 拌粮 / 针筒辅助 |
| 开立依据 | 医生建议 / 自主补充 / 待确认 |
| 反应记录 | 爱吃 / 排斥 / 无变化 / 疑似不适 |
| 风险备注 | 如“与处方粮同时使用，观察便便” |

交互建议：

1. “疗程”与“单次喂食记录”分开。
2. 开启疗程后，可自动生成每日待喂提醒。
3. 如果用户没录热量，也不强制录，只保证可追溯。

## 7. 统计与提醒

### 7.1 第一阶段就值得做的统计

1. 近 7 天喂食次数分布
2. 近 7 天零食次数
3. 近 30 天补剂执行率
4. 换粮计划完成度
5. 饮食异常发生日历

### 7.2 第二阶段可做的高级统计

1. 饮食变化与体重变化关联
2. 零食热量占比趋势
3. 不同主粮的接受度排名
4. 软便/呕吐与某类食物的关联提示
5. 湿粮占比与饮水相关观察

### 7.3 提醒规则建议

1. 零食热量超过每日目标 10% 时提醒
2. 换粮计划超过 2 天未记录执行时提醒
3. 补剂疗程已到结束日时提醒
4. 连续 2 次记录“拒食/只吃一半”时提醒
5. 换粮期间出现呕吐、严重软便、精神差时提醒“建议暂停并咨询兽医”

## 8. 过滤与查询

为了让这个页签真能“查问题”，建议至少支持以下筛选：

1. 按时间筛选：今天 / 近 7 天 / 近 30 天 / 自定义
2. 按类型筛选：主粮 / 罐头 / 零食 / 补剂
3. 按异常筛选：软便 / 呕吐 / 拒食 / 食欲下降
4. 按计划筛选：当前方案 / 某次换粮 / 某个补剂疗程
5. 按关键词搜索：品牌、产品名、口味

## 9. 数据结构建议

如果后面准备开发，我建议不要把所有内容都塞进一张表。

比较稳妥的拆法：

1. `feeding_plans`
   - 当前或历史喂养方案
2. `feeding_records`
   - 每次实际喂食流水
3. `food_transition_plans`
   - 换粮计划
4. `food_transition_steps`
   - 每日/每阶段比例
5. `supplement_courses`
   - 补剂疗程

这样后面扩展统计、提醒、模板会轻松很多。

如果想先快做，也可以先做轻量版：

1. 一张 `feeding_records`
2. 一张 `feeding_plans`
3. 先把换粮和补剂都作为带类型的计划记录

我更推荐先做“轻量版数据结构 + 预留字段”，避免第一版过重。

## 10. MVP 建议

如果这次只做第一版，我建议范围收在下面这组，投入产出比最高：

1. 新增【饮食记录】页签
2. 顶部 4 张摘要卡
3. 当前喂养方案
4. 每日喂食记录时间线
5. 换粮计划
6. 补剂疗程
7. 基础提醒：换粮异常、连续拒食、疗程到期

先不做的内容：

1. 精准热量计算器
2. 自动推荐品牌/剂量
3. 复杂营养分析报表
4. 多猫横向饮食对比

---

## 11. 产品注意事项

1. 补剂/保健品页面应明确是“记录工具”，不是医疗建议工具。
2. 处方粮、疾病相关饮食、长期拒食等场景，应提示在兽医指导下使用。
3. 不要强制用户每次都填热量，否则录入成本会很高。
4. 单位一定要灵活，尤其是 `g / ml / 勺 / 颗 / 条 / 罐 / 袋`。
5. 要支持“从历史记录快速复用”，否则日常录入会很烦。

---

## 12. 我给你的最终建议

如果你想让这个页签真正长期可用，核心不是“再加一个表单”，而是把它做成：

1. 可看计划
2. 可记执行
3. 可跟换粮
4. 可查异常

从产品价值上看，【换粮计划】和【补剂疗程】是最容易让这个模块和普通“备注功能”拉开差距的两个点，建议优先保证。
